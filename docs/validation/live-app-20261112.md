## Windows 管道根因与建议

当前 `crates/aistudio-agent-data/src/server.rs` 以 `ListenerNonblockingMode::Both` 建立监听，并将已接受连接设为非阻塞。interprocess 2.4.6 默认管道缓冲提示为 512 字节。`write_reply` 将 `Ok(0)` 视为 WriteZero 后退出，而连接线程丢弃 `serve` 错误，导致业务日志显示成功但客户端没有完整响应。

临时独立管道复刻当前配置后：3,328 字节 hello 对 Node net 首写为 0；131,314 字节回复对同步 fs 首写 65,536、次写 0。改为正常 PIPE_WAIT 后 net/fs 两种客户端都完整接收。单换 WriteFileEx 为 WriteFile、仍保留 NOWAIT，不解决问题。没有改动正在运行的真实服务。

成熟实现使用正常等待模式加 overlapped 异步 I/O / IOCP，持续处理部分写、背压、取消和断连。正式方案应改 Windows 传输适配层，保留协议、授权与幂等；不能仅增加缓冲或把所有 I/O 改成无法取消的阻塞调用。微软明确说明 PIPE_NOWAIT 不应用于实现异步 I/O：

- https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-type-read-and-wait-modes
- https://learn.microsoft.com/en-us/windows/win32/ipc/synchronous-and-overlapped-input-and-output
- https://docs.rs/tokio/latest/tokio/net/windows/named_pipe/struct.NamedPipeServer.html

总览响应还有独立投影问题：`storyboardValidation` 合计约 5,473,916 字节，`scriptInfo` 354,743 字节，`videoCover` 207,267 字节。建议 summary 只返回列表必要字段、详情按需读取；缩小投影不能替代传输修复。本轮尚未实施这两项修复。
