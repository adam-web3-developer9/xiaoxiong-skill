# 架构

OpenCode/Codex → 小熊AI操作Skill（可选MCP）→ Node CLI/SDK → 本机Unix socket或Windows命名管道 → 应用v2 Session/Grant → AppHost → 共享DesktopService写闸 → 既有账户/配置/草稿/任务owner。

## 应用授权

公开发现文件只含endpoint/protocol/schema等信息，不含可操作业务的token。标准临时目录内的本机实例标记支持自定义数据目录自动发现；客户端核对OS用户、存活PID、根目录descriptor和instanceId，不扫描业务数据或读取旧token。hello协商独立client version与API/schema，不伪装为应用buildId。应用继续检查main/host一致、更新写闸、账户权限。配对申请返回高熵pollSecret和短核对码，授权管理只注册在可信Tauri主窗口原生命令，不注册在Agent业务方法。

授权面板真实挂载于App头部和设置页，收到请求自动打开非模态抽屉，不跳转/卸载当前编辑器；关闭后同一请求不反复弹出，新请求才提示。批准/拒绝/撤销均操作应用权威状态。账户上下文变更使已有授权失效。

默认v1关闭，开发开关保留原协议；开启旧入口明确属于可信本机开发模式，不能当作受v2限制的访问。

## 数据与任务

保持草稿和任务原始模型不变，原业务命令完成落库并发送已提交事件。新项目不写SQLite，不创建另一调度器。原有UI刷新路径保持，外部任务等待采用明确轮询；没有宣称新增了SSE/push订阅。

每次业务请求服务端核scope与资源，真实任务ID必须先查实际归属。批次/工作流控制同样校验。导出和重试区分权限，未知结果不自动重试。跨草稿/全局动作不能通过伪造draftId取得有限草稿grant。

## 渠道和插件

通过现有配置owner事务做字段级合并与秘密写入，普通变更不回写掩码或整份配置。秘密输入直接交现有secret owner，读取采用安全投影和存在状态。插件动态数据通过已存providerId+capability+schema action路由到统一插件宿主，不接受客户端提供的URL/config/secretRef。

对外只提供实际应用显示的信息。manifest配置项可展示writeOnly元数据，不展示秘密默认值/现值；内部安装路径/秘密引用/编码存储快照不会作为公开API。

## Skill层

Skill管理只发现SKILL.md元信息、按需读取正文和参考资料及复制显式本地包。它不增加shell权限，不执行包脚本，不把提示词当授权。可导入、可读和依赖满足分别报告。创作输出通过纯适配函数转正式commands，模型判断创作流程，应用决定合法执行。

## 分发

独立项目不依赖主应用源码运行；主应用补丁单独按固定基线应用。后续仓库只承载独立项目与可审计集成补丁，不推送其它仓库。能力目录与CLI/MCP有契约测试，防止声明了应用未实现的方法。
