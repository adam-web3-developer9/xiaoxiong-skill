This example specifies the integration boundary, not a fabricated application JSON payload:

1. Creative output: separate episode prose, asset descriptions, shot descriptions and prompts into a local review artifact, retaining source package and source section for each item.
2. Live schema: retrieve capabilities, existing draft rows and task actions. Identify the precise advertised command types and fields for each output category.
3. Mapping review: match existing IDs or choose explicitly supported creation commands. Confirm episode ordering, asset references and shot-to-episode relationships. Preserve all unrelated data. Mark unmapped content as unresolved.
4. Validation: construct commands from verified schemas; keep stable commandId/requestId; validate required fields and references before submission.
5. User/app approval: apply only the requested edits via the official endpoint. Any paid generation is a separate authorized task with app account/cost gates.
6. Reconciliation: read back entities and monitor task IDs. Do not automatically resend after an uncertain result.
